# B：五轮往返与理想中继调度

## 任务定义

默认运行5个完整往返，即10个单程。主机保持总 README 的固定巡线：

```text
(0,0) → (0,4) → (1,4) → (1,0) → (2,0)
      → (2,4) → (3,4) → (3,0) → (3,4)
```

首次经过 `(3,4)` 不结束去程，完成末尾补飞后才停留。每次返程按本轮去程反向运动。理想实验统一为1m/格、主机1m/s、中继2m/s、0.1s一步；单程23m，五轮总航程230m。端点各停留1s，部署中继时主机等待；耗时还包含中继调位与最后返场。

起飞前建立全图20个格点、31条相邻格线边和12块货箱的初始占用状态。第一轮使用原型固定站位 `(1,2)`、`(2,4)` 完成基线巡检及节点链路采样。第一轮返程期间移箱、观测和更新地图；第二轮正向开始使用更新地图枚举中继站位，此后每个单程重新规划。地图中的货箱移除改变链路遮挡，主机巡线路径保持固定。

本版本是理想运动学：位置和局部占用观测准确、无观测时延，每个物理跳可立即探测、链路对称、路由瞬时切换、移动中也允许转发。中继按有限速度沿格线运动，不会瞬间到站；不建模起降动力学、电量、碰撞、无线丢包和路由握手。Gazebo 只负责时钟与三维场景显示。

## 两种地图变化

货箱采用 **1基 `(列,行)`** 编号：`(1,1)` 是左下区块，`(3,4)` 是右上区块；无人机格点坐标采用0基。这两类坐标不能混用。

| 模式 | 时刻 | 数量与位置 | 操作方式 |
|---|---|---|---|
| random | 首轮返程的可配置区间内随机一次 | 随机2–4块、互不重复 | 按seed复现，无需输入 |
| window | 首轮返程的手动操作窗口内 | 用户一次指定2–4块 | 终端、JSON命令文件或ROS话题 |
| none | 无 | 不移除 | 无变化对照 |

默认区间是**首轮返程开始运动后的第2–12秒**，不是程序启动后的时间，也不包含此前的中继部署时间。通过 `--window-start`、`--window-end` 调整，终点必须早于返程归位。只允许一次原子移除，不会自动补齐手动任务。

为满足“首轮归位前观测变化”，随机任务只从剩余返程可观测的区块中抽样；手动任务若指定已来不及观测的区块会拒绝。窗口过晚、剩余可观测区块不足2块时，随机模式明确报错。局部理想观测半径默认0.76格，相邻货箱中心进入此范围后才更新在线地图。移除命令只修改环境真值，调度器不会立即得到真值。

同一个命令ID、相同内容重发幂等；相同ID换内容、重复格、越界格、数量不符、窗口外提交均拒绝。拒绝不消耗一次任务额度，窗口内可以纠正重试。

## 本地运行

在此目录运行，Python 3.10及以上，无第三方依赖。Windows 可用 `python -X utf8` 替代 `python3`。

```bash
# 随机模式：五轮往返，几秒内完成虚拟时间实验
python3 demo.py --mode random --seed 42

# 手动窗口：按实际时间演示，首轮返程窗口开放后在当前终端输入命令
python3 demo.py --mode window --interactive --window-start 2 --window-end 12
```

窗口开启时输入：

```text
remove 1,1 2,2 3,4
```

也可运行 `python3 demo.py --mode window --command-file command.json`，窗口内将文件写为：

```json
{"id": "manual-1", "cells": [[1, 1], [2, 2], [3, 4]]}
```

文件模式按实际时间执行。内容未变化不会重复提交；文件暂时不完整时等待下一步读取。若准备了旧文件，它会在窗口开放时立即作为命令提交。

提供一个**脚本注入测试**，在首轮返程第3秒调用同一个手动命令接口，方便无需等待地复现；它不代表已完成真人交互验收：

```bash
python3 demo.py --mode window --scripted-command examples/window_command.json
python3 demo.py --mode none --output outputs/ideal_none
python3 -m unittest discover -s tests -v
```

窗口内无人提交时仍完成五轮，但 `change_executed=false`，CLI退出码为2，不能把它算作窗口移箱成功。相同输出目录会覆盖同名实验产物；用 `--output` 指定独立目录保留不同运行。

旧版单轮协同与协议骨架继续通过 `python3 demo.py --legacy` 运行，仍为2m/格，不能与新版1m/格结果混算。`sitl_bridge.py` 仍为旧版单轮飞控骨架；新版五轮入口为 `ideal_sim` 与 ROS 2 launch。

## 如何判读“第二轮调度优化”

默认首轮固定站位，第二轮起允许从全部20个格点中选择中继站位、保持或返场。枚举421个分配：不使用中继、仅使用R1或R2、使用两个不同站位。每个分配可选择直连、单中继或双中继链式路由。

规划仅使用当前在线地图和已知主机路线，按以下顺序排序：预测断链采样数、弱链路采样数、中继转发跳采样数、部署移动距离、切换次数。采样间距0.5格，完整执行按0.1s步长记录；粗采样的预测不等于完整连续轨迹保证。

`second_outbound` 在同一变更真值地图、相同主机路径、相同当前中继位置下，对照：

1. `first_pass_fixed`：沿用首轮固定站位。
2. `frozen_map`：枚举算法读取旧地图。
3. `updated_map`：相同枚举算法读取更新地图。
4. `selected`：实际选择方案；加载AI插件后可与纯CPU枚举比较。

此对照假设中继已到站，记录部署距离但不模拟该对照的部署时长。完整五轮报告另行统计真实仿真部署过程中的移动、断链与时长。这里的真值仅在评估阶段使用，不送进模型或候选规划输入。

`lexicographic_improvement` 比较更新地图枚举与首轮固定站位，`map_only_improvement` 比较更新地图枚举与旧地图枚举。移箱本身改善传播，不能把第一轮、第二轮的所有差值都算成算法收益；也不保证每组随机移箱都让站位改变。保持原站位以避免无效移动也是合法决策，持平和退化均保留。

## 输出与回放

默认保存到 `outputs/ideal_<mode>_seed<seed>/`：

| 文件 | 内容 |
|---|---|
| report.json | 五轮完成情况、每单程指标、移箱与第二轮对照 |
| trace.csv | 每步主机/中继位置、当前路由、RSSI、地图版本和窗口状态 |
| events.jsonl | 初始化、规划、窗口、移除、观测更新、各单程结束 |
| decisions.jsonl | 调度输入、全部421候选、选择结果和模型回退原因 |
| replay.html | 浏览器打开；时间轴、播放速度、真值/在线地图并排回放 |

候选代价是**在线已知地图计算的代价**，不是未来真值标签。用于后续AI训练时应另行离线评估候选，按完整实验/变化场景划分数据集。

```bash
python3 demo.py --model-plugin your_module:build_model
# 仅演示接口的手写评分器，不是训练模型
python3 demo.py --model-plugin ideal_sim.example_model:build_model
```

CPU保留站位合法性及前两项风险优先约束；无效输出和 `score` 抛异常会回退枚举。模型内部应实现推理时限并在超时时抛 `TimeoutError`；当前同步接口不能强制终止无限阻塞的第三方后端，接实板前应改为进程隔离和异步推理。模型加载错误会明确停止启动，避免悄悄当成AI成功运行。

现有C模块的25维弱链路模型不能直接当本接口的调度模型使用；需在后端明确适配输入和输出，训练新版模型后再报告AI收益。默认实验并未训练AI，也未运行NPU。
