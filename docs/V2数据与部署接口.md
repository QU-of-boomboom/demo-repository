# V2 数据与部署接口

版本：`relay-link-v2`，2026-10-20。Python 权威实现为 `swarm_cooperation/swarm_cooperation/relay_learning/features.py`。

2026-10-21：仿真语义另以 `warehouse-abc-v3` 版本化，详见 [ABC统一契约与验收](ABC统一契约与验收.md)。96维张量结构不变；部署元数据必须声明 `simulation_contract_version`，旧数据/权重不能直接并入新口径。

## 1. 拓扑和单位

- 地面站 G、主机 M、两架中继 R1/R2。
- 链路顺序固定：`G-M, G-R1, G-R2, R1-M, R2-M, R1-R2`。
- 仿真明确采用对称链路。真机应保留上下行原始记录；若沿用六链路接口，适配器必须用同时间槽双向测量的较弱值，任一方向缺失即无效，并重新用这种口径训练。不能只测末跳或单方向就宣称整条路径可用。
- 帧中的坐标、路线进度采用“格”；`cell_m` 换算为米。速度 m/s，时间 s，RSSI dBm，电量为 0–1 比例。
- 规范航线：`(0,0) → (0,4) → (1,4) → (1,0) → (2,0) → (2,4) → (3,4) → (3,0) → (3,4)`，每程 23 格，返程严格逆序。

## 2. 原始 JSONL 帧

每行一个时间槽，推荐显式提供全部六条链路。省略的链路按缺测处理，不能补成良好信号；重复/未知链路 ID 拒绝。下面代码使用占位说明，不能直接作为数据文件：

```json
{
  "schema_version": "relay-link-v2",
  "source": "real",
  "episode_id": "warehouseA-day1-flight001",
  "split_group": "warehouseA-day1-layout1",
  "time_s": 12.3,
  "plan_epoch": 4,
  "state": {
    "main_position": [0.0, 1.0],
    "relay_positions": [[1.0, 2.0], [2.0, 4.0]],
    "relay_targets": [[1.0, 2.0], [2.0, 4.0]],
    "relay_ready": [true, true],
    "relay_eta_s": [0.0, 0.0],
    "relay_battery": [0.9, 0.8],
    "direction": "outbound",
    "progress_cells": 1.0,
    "phase": "FLY",
    "main_speed_mps": 1.0,
    "cell_m": 1.0
  },
  "links": [
    {"link_id":"G-M","rssi_dbm":-70.0,"sample_time_s":12.3,"valid":true},
    {"link_id":"G-R1","rssi_dbm":-61.0,"sample_time_s":12.3,"valid":true},
    {"link_id":"G-R2","rssi_dbm":null,"sample_time_s":12.3,"valid":false},
    {"link_id":"R1-M","rssi_dbm":-65.0,"sample_time_s":12.3,"valid":true},
    {"link_id":"R2-M","rssi_dbm":-73.0,"sample_time_s":12.3,"valid":true},
    {"link_id":"R1-R2","rssi_dbm":-66.0,"sample_time_s":12.3,"valid":true}
  ]
}
```

上例格式完整，但一个帧不足以构造未来标签。需要至少覆盖历史窗和完整预测时域的连续记录，且多个独立采集组覆盖正负样本。

约定：

- `time_s` 为接收端对齐后的单调任务时间；`sample_time_s` 为测量时间，不能拿未来时间戳充当当前数据。
- 上游负责时钟对齐、重采样到 0.1 s 槽和乱序重排。编码器拒绝重复/倒退时间，跳过的整数槽补无效值。
- `plan_epoch` 在主机任务/方向或中继目标计划改变时递增。标签窗口内计划改变时屏蔽对应标签，避免把未宣布的未来动作当成可预测输入。
- `relay_eta_s` 是当时根据已知任务估计的时间，不能填写后来才知道的实际到位时间。
- `source=real` 的文件不得包含 `label_rssi_dbm`。仿真文件中的这个字段只供离线生成标签，不会进入编码器或调度器。
- 不足 20 点的历史左侧补无效槽；测量过期、NaN、无效或未来时间戳均不当作良好信号。
- 真实标签要求未来窗口每个时间槽都有对应的新鲜测量；缺测不自动标成“安全”，也不自动等同于真实业务断链。

## 3. 96 维输入

| 下标，0 开始 | 内容 | 缩放 |
|---|---|---|
| 0–59 | 20 点，每点依次 RSSI、valid、age；由早到晚 | `(RSSI+75)/25`；无效 RSSI=0、valid=0；age/0.5，截到 1 |
| 60–65 | 六条链路的 one-hot 标识 | 0 或 1 |
| 66–77 | 两端点当前、短时计划、部署时域计划坐标，各 4 个数 | 坐标转米后 /10 |
| 78–81 | 航段、路线进度、去返方向、主机速度 | /8、/23、+1或−1、/2 |
| 82–88 | R1 的 xy、目标 xy、ready、ETA、电量 | 坐标米/10、ready 0/1、ETA/6、电量0–1 |
| 89–95 | R2 的相同字段 | 同上 |

历史点在采样当时新鲜有效后，会保留为有效历史；age 表示它距当前时刻的年龄。只有“最新观测是否可用”才使用最大新鲜度门限。每条链路只使用自己的历史。

计划位置来自当前速度、已知主机路线和已宣布的中继目标，不是未来实际位置。当前位置以实时状态为准；中继 ETA 是近似估计，不代表飞行保证。未测过的候选站位不伪造 RSSI 历史；本版本由 CPU 的已知地图模型评估这些候选，MLP 只评估实际节点链路。

导出时会生成含全部字段名的 `feature_contract.json`。更改特征顺序、归一化或时域后必须重新生成数据、训练、校准、导出，不能复用旧权重。

## 4. 输出与阈值

输出 `float32 [1,2]` 的 logits。CPU 逐项 sigmoid：

- 第 0 项：未来 `(t, t+1.5s]` 内是否出现 RSSI `< -75 dBm` 的分数。
- 第 1 项：未来 `(t, t+6s]` 内的相同事件。

两个阈值分别在验证集选定，记录在 `deployment.json`。弱链路标签与仿真 `-88 dBm` 断链统计门限分开；这两个门限都需要真实网卡和业务测量校准。

对多跳路径，可将各跳风险分数求和截到 1，作为保守排序分数。本版没有完成概率校准，不能将该数值写作真实路径故障概率。

## 5. 仿真执行与模型回退

- CPU 评估 421 个站位分配；先检查电量代理和当前上游依赖，再按链路风险、转发占用、移动距离、切换等排序。
- 模型用于提前切换和触发部署重新规划；CPU 仍用已知地图和剩余航线评估候选站位。
- 默认每 0.5 s 推理六条跳，规划检查间隔 5 s。达到规划触发条件时才重选站位。
- 中继起飞 2 s、移动 2 m/s、稳定 0.5 s；部署串行，主机等待。预测时域不够时不能保证“提前预测覆盖整个部署”。
- 路由准备 → 中继就位 → 探测 0.2 s → 提交 → ACK 0.3 s → 释放旧路径。旧 ACK、探测失败、超时不会提交新路径。
- 推理放在独立进程，正常每批限时 0.2 s；超时停用进程并回退。模型加载/预热在任务开始前完成，配置或模型哈希错误会停止启动。
- 目前选用的 `--model-plugin` 是旧的候选评分实验接口，不是本版必需模块，也不能直接加载此预测器。

这些是软件仿真的时序，不表示真实飞控或 Wi-Fi 已完成相应握手。
